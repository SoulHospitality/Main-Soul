## 3. What changes, and why: two separate sources
**3a. Engine code fixes (committed locally as `3caa574`, plus L4/L5 in §3b).** These change what the Financial System **displays** wherever a month has been closed. The migrations do not cause this.

| Fix | Displayed change |
|---|---|
| DEF-PL-01 | A P&L over a range with closed months now includes them |
| DEF-BS-01 | The balance sheet shows current-year earnings after a close and balances |
| DEF-CLOSE-01 and L4 | Closing entries of **past closed months** with an opposite-signed (or contra) P&L balance gain their missing lines; retained earnings change accordingly |
| L5 | Anything posted directly to 303000 stays on the balance sheet |
| DEF-SRC-01, DEF-PER-01 (Phase 7) | A finance page whose data query fails now shows an **error** instead of silently incomplete books, and the closed-month check fails closed. On the restored copy, the new-code run of `compare-books.js` and the smoke test must show **no** such errors; any that appear are real data or query problems to fix before deployment |
| DEF-ACC-01 (Phase 7) | Statements report lines on accounts outside the chart (`integrity.unknown_accounts`); expected empty |

Closing entries are regenerated by `buildJournal` on every request, and frozen copies (`financial_posted_entries`) exclude them, so the fix applies retroactively and live check 6 cannot see it. **Measure it** on the restored copy with `rehearsal/compare-books.js`, old code (`main`) vs new code on the same database (`rehearsal/README.md` §1). Every difference must be explained month by month.

**3b. Migrations 175/176 (uncommitted Phase 5B hardening, never applied anywhere).** These must change **no** existing data and **no** displayed figure. They are checked with the **same** code before and after (`rehearsal/README.md` §4).

The pre-commit review's findings, and what Phase 5B did about each:

The real-PostgreSQL test shows `soul_app` is refused every bypass (TRUNCATE, `DISABLE`/`DROP TRIGGER`, `session_replication_role`, `SET ROLE`, function replacement, key access) while the app's normal writes work.
